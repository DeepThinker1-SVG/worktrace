# Worktrace 写作约定

Worktrace Markdown 是用户、普通编辑器和 Agent 共同维护的项目状态。它记录“项目现在处于什么状态”，不记录某次执行的完整过程。

## 阅读方式

1. 用户主要通过分级标题和标题开头的标记扫读 Worktrace。
2. 工作项标题必须独立表达事项及其当前状态、主要结论或所需行动，不能依赖正文才能理解。
3. 一级标题表示稳定、可独立查看的控制模块；二级标题表示用户需要掌握的成果、计划、风险或决定；三级标题只在二级事项确实需要拆分时使用。
4. 正文只补充标题无法承载的必要原因、影响、验证缺口或下一步。

## 自由标记

1. 使用标题开头的自由标记表达状态或注意力，例如 `[进行中]`、`[待验证]`、`[高风险]` 或 `[需判断]`。
2. 模板中的标记只是适合该文件的参考，不是必须使用的固定词表；可以根据实际事项调整或突破。
3. 只使用有助于用户判断的标记，避免为了分类完整而堆叠标签。

## 更新原则

1. 更新原有工作项，使标题和标记反映当前有效状态，不追加日报式记录。
2. 优先修改标记或标题；正文只在已经失真或缺少关键结论时更新。
3. 不为结构完整机械增加层级或空节点。模板占位内容应按实际情况替换、调整或省略。
4. 只沉淀值得后续保留的状态、验证、阻塞、决定和未覆盖内容。
